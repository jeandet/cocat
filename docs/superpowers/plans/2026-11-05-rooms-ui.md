# Self-service rooms, phase 2: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Put a web UI on the server that already exists: log in and out, list, create, rename, delete and leave rooms, manage one room's members and invitations, accept an invitation, and change your own password.

**Architecture:** NiceGUI is mounted at `/ui` inside the existing FastAPI app with `ui.run_with(app, mount_path="/ui")`. A NiceGUI page is a FastAPI route, so it reads the same `fastapiusersauth` cookie as `/api` does, and it calls the phase 1 service modules (`rooms.py`, `invitations.py`) directly — one implementation, two front ends. Anything with a side effect on live connections (deleting a room, removing a member) lives in `app/actions.py`, which the REST routes and the pages both call. Login and logout are the only two plain routes on the host app: a password belongs in a request body, and clearing a cookie needs a response. A small ASGI middleware feeds the reverse-proxy prefix back into `scope["path"]`, because Starlette mounts need it there and a proxy may strip it.

**Tech Stack:** NiceGUI 3.19 (server-side rendering plus a bundled socket.io), FastAPI, fastapi-users 15, SQLAlchemy 2 async over aiosqlite, anycorn (unchanged — see Task 1), pytest with NiceGUI's `User` simulation for page tests, Starlette `TestClient` and `requests` elsewhere.

**Spec:** `docs/superpowers/specs/2026-11-04-self-service-rooms-design.md` (phase 2 only; phases 3–6 get their own plans). Phase 3 adds sign-up, email verification and password reset pages, so this plan does not grow the login page.

**Review history:** revised twice. A spike on 2026-11-05 (nicegui 3.19.0, fastapi 0.162.0, starlette 1.10.0) answered the open questions: anycorn serves NiceGUI including its websocket, so `cocat serve` stays on anycorn; a prefix-stripping proxy needs a middleware; and the in-process `User` harness needs a `sys.modules` snapshot. A review of the first draft then found, verified against the installed sources: path building was wrong on the two host routes (`root_path` there lacks `/ui`), the UI skipped the socket/file cleanup the REST routes perform, `None` was overloaded to mean both "done" and "refused", dialog markers were ambiguous because `find` does see buttons in closed dialogs, click handlers never re-read the cookie, redirecting pages leaked a NiceGUI client each, and `GET /ui/logout`, `safe_next` and blank room names were under-defended. All of that is fixed below.

## Global Constraints

- Python ≥ 3.10. CI runs 3.10–3.14 on Linux, macOS and Windows. `nicegui >=3.9,<4` is the pin: nicegui 4 needs Python ≥ 3.11.
- `coverage report --fail-under=100` must hold. New code is tested in-process, so it is measured. Do **not** add `# pragma: nocover` to new code. `mount_ui` therefore lives outside the `# pragma: nocover` `CocatApp` class, which only calls it.
- `ruff check src tests`, `ruff format --check src tests` and `mypy src tests` must pass (ruff 0.17.3).
- Run tests with the venv on `PATH`, because the server tests spawn the `cocat` CLI: `export PATH=$PWD/.venv/bin:$PATH`.
- One build or test run at a time, in the foreground. Never start a second test run while one is going.
- Pages call service functions directly. No page makes an HTTP request to our own `/api`; the UI and the REST API are two front ends over the same modules.
- Effects that revoke access — closing sockets, deleting a room file — live in `app/actions.py` and nowhere else. A front end that forgets them would leave a removed member writing.
- There is no second login system. The UI sets and reads exactly the `fastapiusersauth` cookie that `/auth/jwt/login` sets, through the same `CookieTransport`. No session storage, no `ui.storage`, no server-side login state.
- No secret — password, JWT, reset token, invitation token — is ever printed, logged, or put in a path or a query string. An invitation token travels in the URL fragment up to the page, then only in a request body.
- The existing websocket route `/room/{room_id}`, `GET /rooms` and `GET /room/{room_id}/users` keep their URLs and response shapes. The deployed SciQLop plugin depends on them.
- Roles: `owner`, `editor`, `viewer`. The UI only assigns `editor`, because viewers can't be enforced until phase 5. It *displays* whatever role a membership has.
- Datetimes in the DB are naive UTC from `utcnow()`. The UI only formats them.
- NiceGUI's app is a process-wide singleton, so every test that builds a `CocatApp` resets it first: the `app_client` fixture and the `ui_simulation` harness both go through `tests/utils.clean_nicegui()`, which also restores `sys.modules` (NiceGUI evicts the modules that own pages).
- One path convention: `ui_url(request, path)` returns the browser path of a UI page, whether the caller is a page or a host route, with or without a proxy prefix. Nothing else builds a UI path.
- Every control a test clicks or types into carries a stable marker (`.mark("create-room")`), and repeating rows keep their markers unique (`room-<id>`). `find` matches a marker *or* an element's content and clicks the lowest element id among matches, and it sees elements inside closed dialogs.
- One confirmation dialog per page, opened with the action to run; it owns the only `confirm` and `cancel` markers.
- A click handler runs as its own task. Tests assert with `should_see` (which also looks at notifications and retries) rather than by reading `notify.messages` after a fixed sleep.
- Room ids are `uuid4().hex` (`create_room` generates them, names aren't unique). Tests and pages get an id from a service call, never by assuming the name, and test room names are made unique so a substring can't match another row.
- Tasks 1–6 ship as **one release**. They can be separate commits but not separate deploys: from Task 1 until Task 2, `/ui/` redirects to a page that doesn't exist yet.
- `*.secret` files and `.venv/` and `__pycache__/` are already excluded through `.git/info/exclude` in the main checkout. Never stage them.

## Review Focus

1. **A reverse proxy that strips `/cocat`** must still serve `/ui/`, its asset URLs and its socket.io endpoint, and every redirect must carry exactly one prefix. Test owner: Task 1.
2. **A member who lost access** — removed, deactivated, or holding an expired cookie — must be refused by the next action, not served from a stale page: every handler resolves the actor from the page's cookie again. Test owner: Tasks 2 and 3.
3. **An invitation token never reaches a path or a query string**, is only kept in memory, and is not logged. Test owner: Task 4.
4. **`next` on the login form and the request's origin** are attacker-controlled: the redirect target must stay local and cross-site form posts must be refused. Test owner: Task 1.
5. **The existing suite keeps passing** while every `CocatApp` mounts NiceGUI in the same process: no leaked middleware, clients or modules. Test owner: Task 1.
6. **Revoking access has effects outside the database** (open sockets, the room's `.y` file) and they must happen for the UI exactly as for `/api`. Test owner: Task 1.

### Task 1: NiceGUI under anycorn, behind the proxy prefix, with login and logout

This task is the spike, made permanent: it proves the mount works in-process, behind `COCAT_PROXY_PREFIX`, and under the real `cocat serve`, and it lands the plumbing every page needs.

**Files:**
- Create: `src/cocat/app/prefix.py`, `src/cocat/app/actions.py`, `src/cocat/ui/__init__.py`, `src/cocat/ui/layout.py`, `src/cocat/ui/auth.py`, `src/cocat/ui/login.py`, `tests/test_prefix.py`, `tests/test_actions.py`, `tests/test_ui_mount.py`, `tests/test_ui_login.py`
- Modify: `src/cocat/app/routes.py`, `src/cocat/app/rooms.py`, `src/cocat/app/users.py`, `src/cocat/app/app.py`, `src/cocat/cli.py`, `pyproject.toml` (server extra), `tests/utils.py`, `tests/conftest.py`, `tests/test_rooms.py`, `tests/test_routes.py`, `tests/test_server.py`

**Interfaces:**
- Produces `class PrefixPath` in `app/prefix.py`, a pure-ASGI middleware:
  - `__init__(self, app: Any, prefix: str)`; `__call__` copies the scope and, when `prefix` is non-empty and `scope["path"]` is neither `prefix` nor under `prefix + "/"`, sets `scope["path"] = prefix + path`. Websocket scopes take the same path.
  - Docstring: a proxy that strips `/cocat` leaves `path="/ui/rooms"`, and the mounted app routes on `root_path="/cocat/ui"` against that path, so it 404s. Put the prefix back and both agree. Routes that aren't mounts never noticed, which is why the REST API worked without this.
- Produces `class RoomActions` in `app/actions.py`, a frozen dataclass of `connections: Connections` and `update_dir: str`:
  - `async delete_room(self, session, room_id, actor)`: the service call, then `connections.close(room_id)`, then `remove_room_file(update_dir, room_id)`.
  - `async remove_member(self, session, room_id, actor, member_id)`: the service call, then `connections.close(room_id, member_id)`.
  - It exists because the cleanup is what revokes access, and two front ends that each remember it will drift. Docstring says so.
- `app/routes.py`: the delete-room and delete-member routes call these two methods instead of `delete_room`/`remove_member` plus cleanup; `make_api_router` builds one `RoomActions`. `ERROR_STATUS` gains `RoomError: 400` and the handler uses `ERROR_STATUS.get(type(exc), 400)` so a plain `RoomError` is a 400, not a 500.
- `app/rooms.py`: `_room_name(name)` strips and raises `RoomError("Enter a room name")` when empty; `create_room` and `rename_room` use it. Validation belongs with the other service rules, and only `POST /api/rooms` had it.
- Produces in `app/users.py`:
  - `Backend` gains `secret: str`; `get_backend` passes it.
  - `async def user_from_token(session, token: str | None, manager: UserManager, strategy: Any) -> User | None`: `None` when the token is missing, unparsable or expired, or the user is inactive; else the user.
  - `Backend.user_manager(self, session) -> UserManager`: `make_user_manager(SQLAlchemyUserDatabase(session, User), self.secret)`.
  - `async def Backend.resolve_user(self, session, token: str | None) -> User | None`: `user_from_token` with this backend's manager and strategy.
  - `websocket_auth` uses `user_from_token`, keeping today's 1008 close, and now also refuses an inactive account.
  - Remove `# pragma: nocover` from `get_jwt_strategy`: the login route and the UI tests execute it.
- Produces in `ui/__init__.py`:
  - `PAGES_MOUNT = "/ui"`.
  - `@dataclass(frozen=True) class UIContext: db: DB; backend: Backend; actions: RoomActions; check_limit: Callable[[Request], None]`.
  - `def mount_ui(app: FastAPI, ctx: UIContext) -> None`: `app.include_router(make_auth_router(ctx))`, then `ui.run_with(app, mount_path=PAGES_MOUNT, title="cocat")`, then `register_pages(ctx)`. The auth router goes in first: a mount matches any method and would swallow routes added after it; a `POST /ui/login` route added before it still lets `GET /ui/login` reach the page.
  - `def register_pages(ctx: UIContext) -> None`: imports each page module here and calls its `register(ctx)`, so pages never import each other. Tasks 2–5 add one line each.
- Produces in `ui/layout.py` (this task creates `ui_url`, `login_link`, `current_user`, `require_user`, `page_header`, `perform` and `act`; `absolute_url` arrives in Task 3, `ConfirmDialog` in Task 2, so every module stays at 100% coverage commit by commit):
  - `def ui_url(request: Request, path: str) -> str`: `urlsplit`-free string join of the mount's parent prefix and `PAGES_MOUNT` and `path` — `base = request.scope["app_root_path"] if "app_root_path" in request.scope else request.scope.get("root_path", "")`, return `base + PAGES_MOUNT + path`. Inside a page `root_path` is already `/ui` (or `/cocat/ui`) and `app_root_path` is the proxy prefix; on a host route there is no `app_root_path` and `root_path` is the prefix alone. Measured: `/ui/rooms` and `/cocat/ui/rooms` in both cases, with the proxy stripping and keeping the prefix. The docstring records those four cases, because guessing this from `root_path` alone is how the first draft broke.
  - `def login_link(request: Request, next_path: str) -> str`: `ui_url(request, "/login") + "?" + urlencode({"next": next_path})`. `urlencode` escapes `/`, which `quote` does not.
  - `COOKIE_NAME = "fastapiusersauth"`.
  - `async def current_user(ctx: UIContext, request: Request) -> User | None`: `ctx.backend.resolve_user` in a short-lived session, on `request.cookies.get(COOKIE_NAME)`.
  - `async def require_user(ctx, request) -> User | RedirectResponse`: `current_user`, else `context.client.delete()` and `RedirectResponse(login_link(request, request.url.path), 307)`. Deleting the client first is required: NiceGUI creates a client per page request and only collects it when a socket disconnects, and a redirecting page never connects, so without this every signed-out visitor leaks a client and its element tree for the life of the process. `next` is the page's own browser path.
  - `def page_header(request, user) -> None`: a header row with the `cocat` title, links to My rooms (marker `nav-rooms`) and Account (marker `nav-account`), the signed-in email, and `logout_form(ui_url(request, "/logout"))` rendered as HTML.
  - `async def perform(ctx: UIContext, work: Callable[[AsyncSession, User], Awaitable[T]]) -> T | None`: open a session from `ctx.db.async_session_maker()` — a handler runs outside the page request, whose session is closed —, resolve the actor with `ctx.backend.resolve_user` on `context.client.request.cookies.get(COOKIE_NAME)`, and when it is `None` notify `Please sign in again` and return `None`. Otherwise run `work` and return its result; a `RoomError` is notified and gives `None`. Resolving the cookie per action is what makes an expired, deactivated or revoked session stop acting on a page that is still open.
  - `async def act(ctx, work: Callable[[AsyncSession, User], Awaitable[None]]) -> bool`: `perform` over a wrapper that returns `True`, so a service that returns nothing still has a success value. `None` means "refused" and nothing else.
- Produces in `ui/auth.py`:
  - `def same_site(request: Request) -> None`: raises `HTTPException(403)` when `Origin` is present and its netloc is not the `Host` header, or when `Sec-Fetch-Site` is present and not `same-origin`/`same-site`. Missing headers pass: that is an old browser or a test client, and the cookie is `SameSite=Lax` besides.
  - `def safe_next(request: Request, value: str | None) -> str`: `ui_url(request, "/rooms")` unless `value` is a local path — no scheme, no netloc, no `\`, and its path starts with `/` but not `//`. `/\evil.example` and `//evil.example` both fall back, because browsers treat `\` as `/`.
  - `def login_form(action: str, error: str | None) -> str`: `method="post"`, `action` HTML-escaped, one message per error key (`credentials`, `too_many`, `None` for no message), two labelled inputs named `username` and `password` (`type="password"`, `autocomplete="current-password"`), a submit button reading `Log in`, and the line `Accounts are created by an administrator.` No sign-up, no reset link.
  - `def logout_form(action: str) -> str`: a one-button `<form method="post">`.
  - `def make_auth_router(ctx: UIContext) -> APIRouter`, two routes on the host app:
    - `POST /ui/login`: `same_site(request)`; `ctx.check_limit(request)` inside a `try` that turns `HTTPException` into `RedirectResponse(login_link_to_error("too_many"), 303)` — a form post must answer with a page, not JSON. Read `username` and `password` from the form, authenticate in a session with `await ctx.backend.user_manager(session).authenticate(OAuth2PasswordRequestForm(grant_type="password", username=..., password=...))`, and treat `None` or `not user.is_active` as a failure: 303 to `ui_url(request, "/login") + "?error=credentials"`, no cookie. On success `token = await ctx.backend.get_jwt_strategy().write_token(user)`, build `RedirectResponse(safe_next(request, request.query_params.get("next")), 303)` and copy every `set-cookie` header from `await ctx.backend.auth_backend.transport.get_login_response(token)` onto it.
    - `POST /ui/logout`: `same_site(request)`, then 303 to the login page with every `set-cookie` header copied from `await transport.get_logout_response()`; no cookie is required, so a stale page can still sign out.
  - Both routes are on the host app because a password belongs in a body and clearing a cookie needs a response; the docstring says why the rest of the UI does not need routes.
- Produces in `ui/login.py`, `register(ctx)`: `@ui.page("/")` returns `RedirectResponse(ui_url(request, "/rooms"), 307)`; `@ui.page("/login")` resolves `current_user` first and redirects a signed-in visitor to the rooms page, else renders `ui.html(login_form(ui_url(request, "/login") + next_query(request), error_key))` under the heading `Sign in`. The form action is a relative path with the `next` query carried over in the query string, so a TLS-terminating proxy can't turn it into mixed content.
- App wiring: in `CocatApp.__init__`, after the routers and the CORS middleware, `mount_ui(self.app, UIContext(db=db, backend=backend, actions=RoomActions(self.connections, update_dir), check_limit=check_limit))`, then **as the last statement** `self.app.add_middleware(PrefixPath, prefix=root_path)` — `add_middleware` prepends, so the last call is outermost and rewrites the path before routing.
- `cli.py`: the `serve` command prints the UI URL next to its startup message. Keep it inside the `# pragma: nocover` block.
- Produces (tests), in `tests/utils.py`:
  - `@contextmanager def clean_nicegui() -> Iterator[None]`: snapshot `{name: module for name, module in sys.modules.items() if name == "cocat" or name.startswith("cocat.")}`, enter `nicegui_reset_globals()`, call `core.reset()`, yield, and in `finally` restore the snapshot. The reset drops NiceGUI's routes, middleware and clients and evicts the modules that own pages (`cocat`, `cocat.ui`, …), which would otherwise give a later test a second `cocat.app.db` and a second `Base`; `core.reset()` after entering clears the script client that `app.reset()` leaves, which otherwise makes `ui.run_with` raise `KeyError`.
  - `@asynccontextmanager async def ui_simulation(make_app)`: `monkeypatch`-free `os.environ["NICEGUI_USER_SIMULATION"] = "true"` for the duration (it makes `helpers.is_pytest()` true, so `Storage.clear()` skips the client storage teardown would touch after the page is gone), then `with clean_nicegui(): app = make_app()`, `async with app.router.lifespan_context(app)`, `async with httpx.AsyncClient(transport=httpx.ASGITransport(app), base_url="https://testserver") as client: yield User(client)`, and pop the variable at the end. `https` because fastapi-users sets `Secure` cookies, as the REST tests do.
  - `async def log_in(user: User, email: str, password: str, next_path: str | None = None) -> httpx.Response`: posts the form with `follow_redirects=False`, asserts 303 and that the cookie is set, and returns the response.
  - `async def click(user: User, marker: str) -> None`: `user.find(marker=marker).click()`. No sleep: assertions use `should_see`, which retries and reads notifications too.
  - `async def fill(user: User, marker: str, text: str) -> None`: `user.find(marker=marker).type(text)`.
- Produces (tests), in `tests/conftest.py`:
  - `app_client` builds the app inside `clean_nicegui()`, so the REST and websocket suite starts from a clean NiceGUI singleton instead of stacking three middleware layers per test.
  - `@dataclass class UI: user: User; app: FastAPI; db_path: str; update_dir: str; email: str = "ui@test.org"; password: str = "pwd"`, with `async def log_in(self) -> httpx.Response` calling `utils.log_in(self.user, self.email, self.password)`.
  - `@pytest.fixture() async def ui(update_dir, db_path) -> AsyncIterator[UI]`: `await _create_user(UI.email, UI.password, False, db_path)` (the CLI helper, awaited directly — `anyio.run` cannot be used inside a running loop), then `async with ui_simulation(lambda: CocatApp(update_dir, db_path).app) as user: yield UI(...)`. The app must be built inside the simulation, because `CocatApp.__init__` mounts the UI.

- Produces: `async def read_fragment_token() -> str`: `value = await ui.run_javascript("window.location.hash.replace(/^#/, '')")`, then `"" if value is None else str(value).strip()`. A fragment never reaches the server, so the page asks the browser once and the token then lives only in the page's Python scope; the answer arrives in a socket message body, not a URL. An invalid token renders `This invitation is not valid anymore`. With no token, a paste box (`paste-link`, `continue`) sets it from `token_from_text`. Signed out: a `Log in to accept` link from `login_link(request, "/invitation")` and a note that the link must be pasted after signing in. Signed in: `Accept` (`accept-invitation`) calling `accept_invitation`; on success notify `You joined <room>` and navigate to `ui_url(request, f"/rooms/{room.id}")`.
