# Self-service rooms, phase 2: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Put a web UI on the server that already exists: log in and out, list, create, rename, delete and leave rooms, manage one room's members and invitations, accept an invitation, and change your own password.

**Architecture:** NiceGUI is mounted at `/ui` inside the existing FastAPI app with `ui.run_with(app, mount_path="/ui")`. A NiceGUI page is a FastAPI route, so it reads the same `fastapiusersauth` cookie as `/api` does, and it calls the phase 1 service modules (`rooms.py`, `invitations.py`) directly — one implementation, two front ends. The two things NiceGUI's socket can't do are two plain routes on the host app: a login form must be a POST with the password in the body, and logout must be a response that clears the cookie. A small ASGI middleware feeds the reverse-proxy prefix back into `scope["path"]`, because Starlette mounts need it there and a proxy may strip it.

**Tech Stack:** NiceGUI 3.19 (server-side rendering plus a bundled socket.io), FastAPI, fastapi-users 15, SQLAlchemy 2 async over aiosqlite, anycorn (unchanged — see Task 1), pytest with NiceGUI's `User` simulation for page tests, Starlette `TestClient` and `requests` elsewhere.

**Spec:** `docs/superpowers/specs/2026-11-04-self-service-rooms-design.md` (phase 2 only; phases 3–6 get their own plans). Phase 3 adds sign-up, email verification and password reset pages, so this plan does not grow the login page.

**Review history:** revised after a spike run on 2026-11-05 (nicegui 3.19.0, fastapi 0.162.0, starlette 1.10.0). The spike answered the two open questions and changed the plan: anycorn serves NiceGUI including its websocket, so `cocat serve` stays on anycorn; and mounted apps break under a prefix-stripping proxy without a middleware, which Task 1 adds. The spike also fixed the test harness (global NiceGUI state, `sys.modules` eviction, and async page guards) before it was written into the plan.

## Global Constraints

- Python ≥ 3.10. CI runs 3.10–3.14 on Linux, macOS and Windows. `nicegui >=3.9,<4` is the pin: nicegui 4 needs Python ≥ 3.11.
- `coverage report --fail-under=100` must hold. New code is tested in-process, so it is measured. Do **not** add `# pragma: nocover` to new code. `mount_ui` therefore lives outside the `# pragma: nocover` `CocatApp` class, which only calls it.
- `ruff check src tests`, `ruff format --check src tests` and `mypy src tests` must pass (ruff 0.17.3).
- Run tests with the venv on `PATH`, because the server tests spawn the `cocat` CLI: `export PATH=$PWD/.venv/bin:$PATH`.
- One build or test run at a time, in the foreground. Never start a second test run while one is going.
- Pages call service functions directly. No page makes an HTTP request to our own `/api`; the UI and the REST API are two front ends over the same modules.
- There is no second login system. The UI sets and reads exactly the `fastapiusersauth` cookie that `/auth/jwt/login` sets, through the same `CookieTransport`. No session storage, no `ui.storage`, no server-side login state.
- No secret — password, JWT, reset token, invitation token — is ever printed, logged, or put in a path or a query string. An invitation token travels in the URL fragment up to the page, then only in a request body.
- The existing websocket route `/room/{room_id}`, `GET /rooms` and `GET /room/{room_id}/users` keep their URLs and response shapes. The deployed SciQLop plugin depends on them.
- Roles: `owner`, `editor`, `viewer`. The UI only assigns `editor`, because viewers can't be enforced until phase 5. It *displays* whatever role a membership has.
- Datetimes in the DB are naive UTC from `utcnow()`. The UI only formats them.
- NiceGUI state is global per process. Every test that mounts the UI goes through the one harness in `tests/utils.py`, so leaks between tests are fixed in one place.
- Every control a test clicks or types into carries a stable marker (`.mark("create-room")`). `User.find` matches a marker *or* an element's content and clicks the lowest element id when several match, so markers are what keeps a page with repeating rows unambiguous.
- A click handler runs as a separate task, so a test lets it finish before asserting: `await click(user, "create-room")` in `tests/utils.py` wraps `user.find(marker=...).click()` plus an `anyio.sleep`. Assertions on `user.notify.messages` must come after that.
- Room ids are `uuid4().hex` (`create_room` generates them, names aren't unique). Tests and pages get an id from a service call, never by assuming the name.
- Tasks 1–6 ship as **one release**. They can be separate commits but not separate deploys: from Task 1 until Task 2, `/ui/` redirects to a page that doesn't exist yet.
- `*.secret` files and `.venv/` and `__pycache__/` are already excluded through `.git/info/exclude` in the main checkout. Never stage them.

## Review Focus

1. **A reverse proxy that strips `/cocat`** must still serve `/ui/`, its asset URLs and its socket.io endpoint. Starlette matches mounts on `scope["path"]`, and a stripped prefix makes the mount unreachable — the spike reproduced this (404) and the fix. Test owner: Task 1.
2. **An action taken by a member who just lost access** must be refused, not served from a stale page: every click handler re-reads the user and the membership from the DB in its own session. Test owner: Tasks 2 and 3.
3. **An invitation token never reaches a path or a query string**, is only kept in memory, and is not logged. Test owner: Task 4.
4. **`next` on the login form is an open redirect** unless it is restricted to a local path. Test owner: Task 1.
5. **The existing suite keeps passing** while every `CocatApp` now mounts NiceGUI in the same process: REST, websocket and CLI tests must not see leaked global state. Test owner: Task 1.
6. **`base_url` and `root_path`** are not what a naive page assumes. Redirects and absolute share links are built from `scope["root_path"]` only (the spike measured all three cases). Test owner: Tasks 1 and 3.

This task is the spike, made permanent: it proves the mount works in-process, behind `COCAT_PROXY_PREFIX`, and under the real `cocat serve`, and it lands the plumbing every page needs.

**Files:**
- Create: `src/cocat/app/prefix.py`, `src/cocat/ui/__init__.py`, `src/cocat/ui/layout.py`, `src/cocat/ui/auth.py`, `src/cocat/ui/login.py`, `tests/test_prefix.py`, `tests/test_ui_mount.py`, `tests/test_ui_login.py`
- Modify: `src/cocat/app/users.py`, `src/cocat/app/app.py`, `src/cocat/cli.py`, `pyproject.toml` (server extra), `tests/utils.py`, `tests/conftest.py`, `tests/test_server.py`

**Interfaces:**
- Produces: `class PrefixPath` in `app/prefix.py`, a pure-ASGI middleware:
  - `__init__(self, app: Any, prefix: str)`.
  - `__call__` copies the scope, and when `prefix` is non-empty and `scope["path"]` is neither `prefix` nor under `prefix + "/"`, sets `scope["path"] = prefix + path`. Websocket scopes are handled by the same code path.
  - It exists because Starlette matches `Mount` on `scope["path"]`: a proxy that strips `/cocat` leaves `scope["path"] = "/ui/rooms"` while the app's `root_path` is `/cocat`, and the mount returns 404. Routes that aren't mounts work either way, which is why the REST API never needed this. Put that reason in the docstring.
- Produces in `app/users.py`:
  - `Backend` gains `secret: str`. `get_backend` passes it.
  - `async def user_from_token(session: AsyncSession, token: str | None, manager: UserManager, strategy: Any) -> User | None`: `None` when the token is missing, unparsable or expired, or the user is inactive; else the user.
  - `Backend.user_manager(self, session: AsyncSession) -> UserManager`: `make_user_manager(SQLAlchemyUserDatabase(session, User), self.secret)`. The websocket auth and the CLI build the same manager; after this they call this.
  - `async def Backend.resolve_user(self, session: AsyncSession, token: str | None) -> User | None`: `user_from_token` with this backend's manager and strategy. Every UI page uses it.
  - `websocket_auth` is rewritten to use `user_from_token`, keeping today's 1008 close. It now also refuses an **inactive** account, which it silently allowed before.
  - Remove `# pragma: nocover` from `get_jwt_strategy`: the login route and the UI tests execute it.
- Produces in `ui/__init__.py`:
  - `PAGES_MOUNT = "/ui"`.
  - `@dataclass(frozen=True) class UIContext: db: DB; backend: Backend; check_limit: Callable[[Request], None]`.
  - `def mount_ui(app: FastAPI, ctx: UIContext) -> None`: `app.include_router(make_auth_router(ctx))`, then `ui.run_with(app, mount_path=PAGES_MOUNT, title="cocat")`, then `register_pages(ctx)`. The auth router goes in first: a NiceGUI mount is a `Mount`, which matches any method, so a route added after it is unreachable. A `GET /ui/login` still lands on the page, because the auth route only matches `POST` and Starlette keeps looking.
  - `def register_pages(ctx: UIContext) -> None`: calls each page module's `register(ctx)`. Tasks 2–5 add one line each; it exists from the start so no page module has to import its siblings.
- Produces in `ui/layout.py` (this task only creates the two helpers it uses; the header, the page guard and `perform` arrive in Task 2, `absolute_url` in Task 3, so every module stays at 100% coverage commit by commit):
  - `def prefixed(request: Request, path: str) -> str`: `request.scope.get("root_path", "") + path`. This is the browser-visible absolute path of a page: the spike measured `/ui/rooms` with no prefix, and `/cocat/ui/rooms` both when the proxy strips `/cocat` and when it keeps it, because Starlette appends the mount path to `root_path`. Docstring says so.
  - `async def current_user(ctx: UIContext, request: Request) -> User | None`: resolves the `fastapiusersauth` cookie with `ctx.backend.resolve_user` in a short-lived session.
  - Docstring on the module: paths inside a page must be built with `prefixed`, never hard-coded, because a page is reached through a mount.
- Produces in `ui/auth.py`:
  - `def make_auth_router(ctx: UIContext) -> APIRouter` with two routes, both on the host app:
    - `POST /ui/login`: calls `ctx.check_limit(request)` first, so the form is rate-limited like `/auth/jwt/login`. Reads `username`, `password` from the form and `next` from the query string, authenticates in a session from `ctx.db.async_session_maker()` with `await ctx.backend.user_manager(session).authenticate(OAuth2PasswordRequestForm(grant_type="password", username=..., password=...))`, and treats `None` or `not user.is_active` as a failure: 303 to the login page with `?error=1`, no cookie. On success, `token = await ctx.backend.get_jwt_strategy().write_token(user)`, then build `RedirectResponse(safe_next(request, next_value), 303)` and copy every `set-cookie` header from `await ctx.backend.auth_backend.transport.get_login_response(token)` onto it. No body.
    - `GET /ui/logout`: 303 to the login page with every `set-cookie` header copied from `await transport.get_logout_response()`. It is not rate-limited. It's a `GET` on purpose: logging out has nothing to protect, and a link is the one thing a click can follow without JavaScript. Login is the opposite case — a password in a URL path or query is exactly what the constraints forbid, so it must be a form post.
  - `def safe_next(request: Request, value: str | None) -> str`: `prefixed(request, "/rooms")` by default; otherwise `value` only when it starts with exactly one `/`, so `//evil.example` and `https://evil.example` both fall back to the default. That's the open-redirect guard.
  - `def login_form(action: str, error: bool) -> str`: the HTML form, `method="post"`, `action` HTML-escaped, an error line `Wrong email or password.` when `error`, two labelled inputs named `username` and `password` (`type="password"`, `autocomplete="current-password"`), a submit button reading `Log in`, and the line `Accounts are created by an administrator.` No sign-up, no password-reset link. Tests assert on those exact strings, so the page and the tests share them.
- Produces in `ui/login.py`:
  - `register(ctx)`: `@ui.page("/")` returns `RedirectResponse(prefixed(request, "/rooms"), 307)`; `@ui.page("/login")` renders the form under the heading `Sign in` — `await current_user(ctx, request)` first, and when a user is found returns `RedirectResponse(prefixed(request, "/rooms"), 307)`; otherwise `ui.html(login_form(str(request.url), request.query_params.get("error") == "1"))`. Using `str(request.url)` as the action keeps the `next` query and drops nothing; the page itself never reads the password.
- App wiring: in `CocatApp.__init__`, after the routers and the CORS middleware, call `mount_ui(self.app, UIContext(db=db, backend=backend, check_limit=check_limit))`, and **as the last statement** `self.app.add_middleware(PrefixPath, prefix=root_path)` — `add_middleware` prepends, so the last call is the outermost layer and rewrites the path before Starlette routes.
- `cli.py`: the `serve` command prints the UI URL once next to its existing startup message. Keep it inside the `# pragma: nocover` block.
- Produces (tests), in `tests/utils.py`:
  - `@asynccontextmanager async def ui_simulation(make_app: Callable[[], FastAPI])`:
    - Set `NICEGUI_USER_SIMULATION=true` for the duration. NiceGUI's `helpers.is_pytest()` reads it, and with it `Storage.clear()` skips the client storage that teardown would otherwise touch after the page is gone.

    - `with nicegui_reset_globals(): core.reset(); app = make_app()` — `nicegui_reset_globals()` resets UI globals and removes non-`/_nicegui/` routes from `core.app`; the extra `core.reset()` drops the script client `app.reset()` leaves behind, which otherwise makes `ui.run_with` raise `KeyError` — then `async with app.router.lifespan_context(app)` and `async with httpx.AsyncClient(transport=httpx.ASGITransport(app), base_url="https://testserver") as client: yield User(client)`.
    - `https` because fastapi-users sets `Secure` cookies, as in the REST tests.
  - `async def log_in(user: User, email: str, password: str, next_path: str = "/ui/rooms") -> httpx.Response`: posts the login form with `follow_redirects=False`, asserts 303 and that the cookie is now set, and returns the response.
  - `async def click(user: User, marker: str) -> None`: `user.find(marker=marker).click()`, then `await anyio.sleep(0.05)` so the handler task runs before the test asserts.

### Task 2: My rooms page

**Files:**
- Create: `src/cocat/ui/rooms.py`, `tests/test_ui_rooms.py`
- Modify: `src/cocat/ui/__init__.py` (`register_pages` gains this page), `src/cocat/ui/layout.py`

**Interfaces:**
- Produces in `ui/layout.py`, all first used here:
  - `def login_link(request: Request, next_path: str) -> str`: `prefixed(request, "/login") + "?next=" + quote(next_path)`.
  - `async def require_user(ctx: UIContext, request: Request) -> User | RedirectResponse`: `current_user`, and when there is none `RedirectResponse(login_link(request, request.url.path), 307)`. Returning a `Response` from a page makes NiceGUI return it instead of rendering, which the spike verified. `next` is the page's own browser path, so a signed-out visitor comes back where they were.
  - `def page_header(request: Request, user: User) -> None`: a NiceGUI header row with the `cocat` title, links to My rooms (marker `nav-rooms`) and Account (marker `nav-account`), the signed-in email, and a Log out button (marker `logout`) whose handler is `ui.navigate.to(prefixed(request, "/logout"))`. The route is a `GET`, so a plain navigation is all it needs.
  - `async def perform(ctx: UIContext, user_id: UUID, work: Callable[[AsyncSession, User], Awaitable[T]]) -> T | None`: opens its own session — a click handler runs outside the page request, whose session is already closed —, re-loads the user by id, runs `work`, and returns its result. On `RoomError` it calls `ui.notify(str(error))` and returns `None`. `work` must return a non-`None` value: `None` is reserved for "refused". Re-reading the user and the membership here is what makes a stale page harmless.
- Produces: `def register(ctx: UIContext) -> None` in `ui/rooms.py`, registering `@ui.page("/rooms")`.
- The page starts with `user = await require_user(ctx, request)`; a `RedirectResponse` is returned as-is.
- `@ui.refreshable async def room_list()` renders one `ui.row` per `(room, role)` from `list_user_rooms(session, user.id)` in its own session: the room name, the role as text, a link to `prefixed(request, f"/rooms/{room.id}")`, and the buttons the role allows — `Rename` and `Delete` for the owner, `Leave` for everyone else. Every button opens a `ui.dialog` with a confirm/cancel pair, because two of the three destroy data. This is why an owner never sees `Leave`: `remove_member` refuses it with 409, so offering it would be a dead end.
- Markers, because rooms repeat: the input is `new-room-name`, the button `create-room`, and each row gets `room-<id>`, `rename-<id>`, `delete-<id>`, `leave-<id>`. Every dialog uses the same `confirm` and `cancel` markers: only one is open at a time and hidden elements are out of scope for `find`.
- Create form: `ui.input("New room name")` plus a `Create` button. On click, a stripped empty name is refused by the page itself with `ui.notify("Enter a room name")` — the REST schema's `min_length=1`, which the service doesn't enforce. Otherwise `perform(ctx, user.id, lambda session, user: create_room(session, user, name))`, and on a non-`None` result clear the input, `ui.notify("Room created")` and `await room_list.refresh()`. Names are not unique: two rooms may share one, and the list shows both, each with its own id.
- Rename, delete and leave follow the same shape through `rename_room`, `delete_room` and `remove_member(session, room_id, actor, user.id)`, each followed by `await room_list.refresh()`. A `RoomError` is reported by `perform`; nothing else is caught.

### Task 4: Accept-invitation page

**Files:**
- Create: `src/cocat/ui/invitation.py`, `tests/test_ui_invitation.py`
- Modify: `src/cocat/ui/__init__.py`

**Interfaces:**
- Produces: `def register(ctx: UIContext) -> None` in `ui/invitation.py`, registering `@ui.page("/invitation")`.
- Produces: `async def read_fragment_token() -> str`: `value = await ui.run_javascript("window.location.hash.replace(/^#/, '')")`, then `"" if value is None else str(value).strip()`. A fragment never reaches the server, so the page asks the browser for it once; the answer comes back in a socket message body, and the value then lives only in the page's Python scope. That is the whole reason this page exists as a separate route instead of `/invitation/{token}`.
- Produces: `def token_from_text(text: str) -> str`: the part after the first `#` when there is one, else the stripped text. It parses a pasted share link, because the fragment does not survive the login redirect.
- The page: `token = await read_fragment_token()`; with no token it renders a paste box (`ui.input("Paste your invitation link")`, marker `paste-link`, and a `Continue` button, marker `continue`) that sets the token from `token_from_text` and refreshes the section.
- `@ui.refreshable async def invitation()`: `preview_invitation(session, token)` and render the room name, the role, the inviter's email and the expiry date. Logged out: a `Log in to accept` link built with `login_link(request, "/invitation")` and the note that the link must be pasted after signing in — the hash is gone by then. Logged in: an `Accept` button (marker `accept-invitation`) calling `accept_invitation(session, token, user)`; on success `ui.notify("You joined <room>")` and `ui.navigate.to(prefixed(request, f"/rooms/{room.id}"))`; on `RoomError` the message ("Invitation not found", "This invitation is for another email address", …) is shown by `perform`.

### Task 5: Account page

**Files:**
- Create: `src/cocat/ui/account.py`, `tests/test_ui_account.py`
- Modify: `src/cocat/ui/__init__.py`

**Interfaces:**
- Produces: `def register(ctx: UIContext) -> None` in `ui/account.py`, registering `@ui.page("/account")`.
- The page shows the signed-in email and a change-password form: three `ui.input`s with `password=True` labelled `Current password`, `New password`, `Repeat new password`, markers `current-password`, `new-password`, `repeat-password`, and a `Change password` button (marker `change-password`).
- The click handler refuses in the page, without touching the DB, when the two new fields differ (`ui.notify("The new passwords differ")`) or are empty (`ui.notify("Enter a new password")`).
- It then checks the current password inside its own session: `await ctx.backend.user_manager(session).authenticate(OAuth2PasswordRequestForm(grant_type="password", username=user.email, password=current.value))`. `None` means `ui.notify("Wrong password")` and nothing changes.
- Otherwise `await manager.update(UserUpdate(password=new.value), user)` — the argument order is `(update, user)` in fastapi-users 15 — then clear the inputs and `ui.notify("Password changed")`.
- `manager.update` can raise `fastapi_users.exceptions.InvalidPasswordException`; the handler catches it and notifies `error.reason`. The policy is fastapi-users' own `validate_password`, so the UI adds no rules of its own and reports its refusal verbatim.
- This page doesn't go through `perform`, because `perform` opens the session after the page-side checks and only translates `RoomError`; the handler opens one session for both the check and the update.
